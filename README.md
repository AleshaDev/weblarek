# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные
В приложении используются следующие  интерфейсы для описания данных:
### Интерфейс Товар (IProduct)
Структура товара.

interface IProduct {
  id: string; - ID товара
  description: string; - описание товара
  image: string; - путь к изображению товара
  title: string; - заголовок товара
  category: string; - категория товара
  price: number | null; - цена 
}


### Интерфейс Покупатель (IBuyer)
Структура покупателя.

interface IBuyer {
  payment: TPayment; - тип оплаты
  email: string; - адресс электронной почты
  phone: string; - номер телефона
  address: string; - адрес доставки
}


## Модель данных
## Класс Products
Отвечает за хранение и работу с каталогом товаров. Поля:

Зона ответственности:
  хранение полного списка товаров;
  управление текущим выбранным товаром для детального отображения.

`_items: IProduct[]` — массив объектов товаров (каталог).
`selectedProduct: IProduct | null` — текущий выбранный товар для детального отображения (может быть null, если товар не выбран).

Методы:
`setItems(items: IProduct[]): void` - сохраняет массив товаров в модели.
`getItems(): IProduct[]` - возвращает полный массив товаров.
`getProductById(id: string): IProduct | null` - находит и возвращает товар по его идентификатору.
`setSelectedProduct(product: IProduct): void` - устанавливает выбранный товар для детального отображения.
`getSelectedProduct(): IProduct | null` - возвращает текущий выбранный товар.

## Класс Cart
Управляет списком товаров, выбранных пользователем для покупки.

Зона ответственности:
  хранение списка выбранных товаров;
  расчёт стоимости и количества товаров в корзине;
  проверка наличия товаров.

`items: IProduct[]` — массив товаров, добавленных в корзину.

Методы:
`getItems(): IProduct[]` - возвращает список товаров в корзине.
`addItem(item: IProduct): void` - добавляет товар в корзину.
`removeItem(item: IProduct): void` - удаляет товар из корзины.
`clear(): void` -  очищает корзину (удаляет все товары).
`getTotalPrice(): number` - рассчитывает и возвращает общую стоимость товаров в корзине.
`getItemCount(): number` - возвращает количество товаров в корзине.
`hasItem(id: string): boolean` - проверяет наличие товара в корзине по идентификатору.

## Класс Buyer 
Хранит и управляет данными покупателя, необходимыми для оформления заказа.

Зона ответственности:
  хранение контактной информации и способа оплаты;
  валидация данных;
  обновление отдельных полей без потери существующих данных.

`payment: TPayment | null` — выбранный способ оплаты (может быть null);
`email: string | null` — электронная почта покупателя (может быть null);
`phone: string | null` — номер телефона покупателя (может быть null);
`address: string | null` — адрес доставки (может быть null).

Методы:
`updateData(data: Partial<IBuyer>): void` - обновляет данные покупателя. Позволяет обновить одно или несколько полей, не затрагивая остальные.
`getData(): IBuyer` - возвращает все данные покупателя в виде объекта.
`clearData(): void` - очищает все данные покупателя (устанавливает поля в null).
`validate(): ValidationResult` - выполняет валидацию всех полей данных покупателя. Возвращает объект с ошибками для полей, не прошедших валидацию.
  Возвращаемое значение: объект типа ValidationResult, где ключи — имена полей, значения — строки с описанием ошибки. Если поле валидно, оно отсутствует в объекте.
  Пример:
    {
    payment: 'Не выбран вид оплаты',
    email: 'Укажите емэйл',
    }

### Интерфейс Формы (IOrderForm)
Описывает структуру данных, которые пользователь заполняет в формах заказа (адрес, оплата, контакты). Поля опциональны, так как заполняются поэтапно.

```typescript

## Список событий

В приложении используются следующие события:

  `modal:open` — открытие модального окна.
  `modal:close` — закрытие модального окна.
  `basket:open` — открытие корзины (клик по кнопке корзины в шапке).
  `card:select` — выбор карточки товара в каталоге (для открытия превью).
  `order:open` — начало оформления заказа (клик "Оформить" в корзине).
  `order.payment:change` — изменение типа оплаты в форме заказа.
  `order.address:change` — изменение адреса в форме заказа.
  `contacts.email:change` — изменение email в форме контактов.
  `contacts.phone:change` — изменение телефона в форме контактов.
  `order:submit` — подтверждение первого шага заказа (переход к контактам).
  `contacts:submit` — подтверждение формы контактов (финальная отправка заказа).

  `items:change` - изменение списка товаров (каталога).
  `preview:change` - изменение выбранного товара (открытие превью).
  `cart:change` - изменение списка товаров в корзине (добавление/удаление/очистка).
  `buyer:change` - изменение данных покупателя в формах заказа.


  ## Презентер
Роль Презентера выполняет код в файле `src/main.ts`.
Взаимодействие осуществляется через события.
Логика обработки событий:
1. Загрузка данных: При старте приложения загружается список товаров с сервера.
2. События Модели: При изменении данных в моделях (каталог, корзина, пользователь) генерируются события, которые обновляют соответствующие представления (галерея, счетчик корзины, ошибки форм).
